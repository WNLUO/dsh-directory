# 总控后端 · 备忘

> 这是「总控后端」的常驻笔记：术语、部署现状、已定/待定的设计。重要变化随手更新这里，
> 后面找东西先看这一页，不用再去扫代码。

## 术语

- **总控后端** = 本项目（仓库 `WNLUO/dsh-directory`，代码在 `rust/`）。它是一张「设备 → 连接地址」
  的地址目录：设备长连接上报地址，APP 长连接查询/订阅地址。不代理数据流量。

## 部署现状（线上）

- 服务器：`SHIYAN`（Rocky Linux 9，x86_64），与官网共用域名。
- 二进制：`/opt/dsh-directory/dsh-directory`，systemd 服务名 `dsh-directory`，只监听 `127.0.0.1:8787`。
- 配置：`/opt/dsh-directory/dsh-directory.env`（只放 `BIND`）。
- 公网入口：`https://ai-hub.wnluo.com/findme/`；WebSocket 走 `/findme/ws/device`、`/findme/ws/app`。
- 反代：宝塔伪静态 `html_ai-hub.wnluo.com.conf` 里追加的 `location /findme/`（片段见 `deploy/nginx-location.conf`）。
- 存储：**全内存、单实例**，进程重启清空；设备重连即恢复。不接 Redis（决定：只放一台总控）。
- 身份：设备注册开放（已去掉 `ENROLL_SECRET`）；每台设备一枚令牌，注册时下发，插件转交 APP，
  APP 拿它查询/订阅。令牌只保护「查地址」一侧，设备注册本身不校验来源。

## 防滥用与容量（已实现）

核心思路：**注册不是永久占位，而是按「最近有没有 APP 来查它」动态淘汰。** 默认值都可用环境变量覆盖。

1. **按 APP 关注度过期**：每条记录记一个「最近被 APP 查询/订阅」的时间。后台每 30 秒清理，超过
   `REGISTRATION_TTL_SECS`（默认 900 秒 = 15 分钟）没有任何 APP 关注的记录就丢掉；新注册给同样
   长度的宽限。真设备会被 APP 的查询不断续期，乱注册的永远不会被查，所以会自然过期。
2. **满载时优先淘汰「没人查」的**：`MAX_DEVICES`（默认 10 万）到线后，再来新设备就踢掉「最久没被
   APP 查、且没有活跃订阅」的那条，把容量让给真正在被使用的设备；实在全都有人在用就快速拒绝
   （`server busy`），不硬扛。
3. **CC 洪峰**：新注册走全局令牌桶（`REG_RATE_PER_SEC` 默认 500/s、`REG_RATE_BURST` 默认 1000），
   超了直接快速拒绝，保护进程别被拖垮；再加每 IP 并发连接上限（`MAX_CONNS_PER_IP` 默认 50）做粗挡
   （注意流量过 CDN，真实客户端 IP 要从代理头取，精度有限）。
4. 都做在内存里、O(1)，不引额外组件。

**已采纳的取舍**：严格「没人查就丢」会把「设备还在线、只是 APP 这一阵没打开」的真设备也丢掉。
处理方式是丢记录时一并断开它的控制连接，插件按退避自动重连补报——数据连接走中转、与控制连接无关，
所以不影响手机连设备，只影响「查地址」那一瞬间。用户已确认接受这个抖动。

## 插件 / APP 集成（计划，未实现，均为内置、用户无感）

- **内置常量**：总控地址（`https://ai-hub.wnluo.com/findme` 与对应 wss）在插件和 APP 里各写一份，
  随包内置，用户不配置。
- **插件**：启动后连 `/ws/device`，把全部地址（中转 / 局域网 / IPv6 / 直连）上报；地址变化再报；
  拿到令牌存下来，经「插件 ↔ APP」已有的那条链路交给 APP；断线按退避重连。
- **APP**：从插件拿到控制地址与令牌，连 `/ws/app` 查询 / 订阅这台设备的地址，把这组地址当作
  「发现当前该走哪条中转」的又一个来源，并缓存最近可用的一条。全程内部完成，不出现任何界面设置。
