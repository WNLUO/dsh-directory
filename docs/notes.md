# 总控后端 · 备忘

> 这是「总控后端」的常驻笔记：术语、部署现状、已定/待定的设计。重要变化随手更新这里，
> 后面找东西先看这一页，不用再去扫代码。

## 术语

- **总控后端** = 本项目（仓库 `WNLUO/dsh-directory`，代码在 `rust/`）。它是一张「设备 → 连接地址」
  的地址目录：设备长连接上报地址，APP 长连接查询/订阅地址。不代理数据流量。

## 部署现状（线上）

- 服务器：`SHIYAN`（Rocky Linux 9，x86_64），与官网共用域名。
- 二进制：`/opt/dsh-directory/dsh-directory`，systemd 服务名 `dsh-directory`，只监听 `127.0.0.1:8787`。
- 配置：`/opt/dsh-directory/dsh-directory.env`（`BIND` 等覆盖）；服务单元指定令牌路径
  `/var/lib/dsh-directory/tokens.jsonl`，由 `StateDirectory` 创建服务用户可写的 700 目录。
- 公网入口：`https://ai-hub.wnluo.com/findme/`；WebSocket 走 `/findme/ws/device`、`/findme/ws/app`。
- 反代：宝塔伪静态 `html_ai-hub.wnluo.com.conf` 里追加的 `location /findme/`（片段见 `deploy/nginx-location.conf`）。
- 存储：**单实例**，在线设备的密文载荷、订阅和限速驻内存；只把设备令牌及最近注册时间写入追加
  日志，注册成功前完成持久写入。重启后沿用原令牌，在线地址等待插件重新上报。日志定期压缩，
  令牌文件需要持久卷/备份；不接 Redis。总控不持 HK，解不开地址载荷。
- 身份：每台设备一枚令牌。首次注册总控下发，之后重连/覆盖必须带同一枚（拿不出就拒绝，防冒充）；
  插件把令牌落在 relay.json 并在重连 URL 上带上，同时经状态心跳转交 APP。APP 拿它查询/订阅。
  总控只认可自己文件中保存的令牌，不采信未知实例自带的旧令牌；文件损坏则启动失败，写入失败不
  返回注册成功。首次升级前的内存令牌无法自动导入，升级后首次注册仍会签发并同步一次新令牌。

## 端到端加密（已实现）

- 复用历史离线 blob 的 HK 信封：AES-256-GCM，`{v:1,z:0,n,c}`，AAD `dsh-history-v1|control|<instanceId>`；
  插件 `lib/mirror/history-blob.cjs` 封、APP `services/viewmodels/history-blob.ts` 开，两端逐字节一致。
- 总控只存 `payload` 密文串，不解析、不持钥；HK 只在配对时下发给该设备的手机。
- 取舍：总控盲存，就不能在服务端按地址做公用中转编址/负载均衡，那类逻辑只能放在插件/APP 侧。

## 地址真相模型（定论）

- 这些地址都是**宿主的地址**，宿主是唯一真源。总控只是「宿主地址本」的加密公告板：**只有宿主写，APP 只读**。
- APP 改地址 = 给宿主下命令（先送达、宿主确认才生效），不是另一份并行的真相。
- 兜底查询：APP 拿到宿主公告的地址后**以它为准**，压过本地那条过期 / 没送达的编辑；本地没送达的改动不算数。
- 所以「谁先改、用哪个」不成立——永远以宿主公告为准，APP 没送达的改动不参与。

实现状态：插件上报全部地址（加密）已完成；APP 侧「以总控结果覆盖本地过期地址 + 临时没送达不当真相」已实现（在 APP，尚未提交：所在文件同时有另一条对话的改动）。

## 防滥用与容量（已实现）

注册没有额外口令，靠「令牌绑定 + 容量上限 + 限速」收口，默认值可用环境变量覆盖：

1. **令牌绑定防冒充**：首次注册发一枚令牌；之后重连/覆盖必须带同一枚，否则拒绝。只知道
   `instanceId`、拿不出令牌的人改不动别人地址、也查不了。
2. **令牌表也有上限**：`MAX_TOKENS`（默认 20 万）到线后淘汰「最久没来注册」的，挡住「不停换
   instanceId 撑爆内存」。被淘汰的设备重连拿新令牌，插件自行更新并转交 APP。
3. **满载优先淘汰「没人查」的**：`MAX_DEVICES`（默认 10 万）到线后，踢掉「最久没被 APP 查、且
   没有活跃订阅」的那条腾位；全都在用就快速拒绝（`server busy`）。
4. **CC 洪峰**：全局令牌桶（`REG_RATE_PER_SEC` 默认 500/s、`REG_RATE_BURST` 默认 1000）+ 每 IP
   并发上限（`MAX_CONNS_PER_IP` 默认 50，过 CDN 时真实 IP 从代理头取、精度有限）。
5. 不再按「没人查就断开」做定时清理——那会和插件断线重连互相打架、造成连接风暴；闲置只靠上面的
   满载淘汰 + 限速来兜。

## 插件 / APP 集成（已接入，均为内置、用户无感）

- **内置常量**：总控地址（`https://ai-hub.wnluo.com/findme` 与对应 wss）内置在插件（`lib/relay/control.js`，
  可用 `DSH_CONTROL_URL` 覆盖联调）与 APP 侧；用户不配置。
- **插件**：把本机**全部连接地址**（中转含自建 / 局域网 / IPv6 / 直连）用 HK 封成密文上报；地址变化推
  update；令牌落 relay.json、重连带上，并经已鉴权的状态心跳交给 APP；断线退避重连。总控看不到内容。
- **APP**：心跳里的 `control` 落进会话；所有直接地址都探不通时（且不在「只走局域网 / 只走直连」两档），
  用令牌连 `/ws/app` 订阅一次拿回密文、用本机 HK 解开后并入会话（中转排队首、局域网/IPv6 进候选）
  作为又一条发现来源；刚判离线时主动催一次，带回 60s 节流、离线跳过、失败静默。
- 两侧测试：插件 `test/control-addresses.test.cjs`、`test/control-client.test.cjs`（含真 WebSocket 与加解密）；
  APP 侧 `tsc` 通过、相关守卫绿。后端定向测试覆盖令牌绑定/上限/限速/满载淘汰，以及令牌跨重启
  保留、在线记录不恢复、未知令牌不采信、持久写入失败、日志压缩与未完成尾记录恢复。
